## 1. 🎯 Project Vision & Context (The "Why")
The **Transition Finance Credibility Index (TFCI)** is an institutional-grade dashboard designed to track, score, and visualize global capital deployment in the energy transition. 

It answers a critical question: *Are jurisdictions actually executing on their transition finance commitments, or is it just intent?* 
The platform tracks **213 jurisdictions** across **20 sectors** and **5 pillars**, assigning them a "Credibility Band" (High, Medium, Low) based on rigorous, evidence-backed mathematical scoring.

---

## 2. 📊 Data Provenance & Lifecycle (The "What")
The data powering TFCI is highly curated and comes from authoritative global sources. 

### Current Data Sources:
- **GEM (Global Energy Monitor):** Primary source for infrastructure tracking (Coal, Gas, Oil, Solar, Wind, Hydro, etc.).
- **World Bank / IMF:** Macroeconomic indicators, FX rates, and capital flow data.
- **National Ministries & Central Banks:** Direct policy and financial close evidence.

### The Data Pipeline:
1. **Ingestion (`data/ingest/`):** Raw files (CSVs, Excel, ZIPs from GEM) are dropped here. *Note: Large raw files are kept out of Git via `.gitignore` and stored in local/cloud archives.*
2. **Staging & Evidence (`data/evidence/`):** Specific data points are verified against immutable source documents (e.g., `SRC-001_neom_blackridge.md`).
3. **The Ledger (`data/ledger_events.csv`, `data/score_history.csv`):** The immutable system of record. Once a score is finalized, it is written here.
4. **Frontend Payload (`web/data/TFCI_frontend_payload_v2.json`):** A highly optimized, flattened JSON file generated by the backend specifically for the Next.js frontend to consume.

*Future State:* The system is designed for continuous "Collection Cycles" where automated agents will scrape, verify, and ingest new data sources automatically.

## 3. ⚙️ The Core Engine & Math (The "How")
The "brain" of TFCI is written in **Python**. It is entirely deterministic—meaning the same input data will *always* produce the exact same output scores. No "black box" AI is used for the core math.

### Key Backend Directories:
- **`src/tfci_engine.py`**: The core mathematical engine. This is where the raw data is transformed into credibility scores, execution ratios, and capital aggregations.
- **`tfci_app/engine/`**: The application wrapper for the engine, handling execution flows and pipeline triggers.
- **`tfci_app/pipelines/`**: Scripts that orchestrate the data flow (e.g., `aggregate_project_capital.py`, `promote_trusted_staging.py`).
- **`tfci_app/agents/`**: (Future/In-progress) AI and automated agents designed to harvest evidence, verify staging data, and update the ledger.

## 4. 🖥️ Frontend & Deployment Architecture (The "Where")
The user-facing dashboard is a **Next.js (React)** application, deployed as a **Static Site** on **Cloudflare Pages**.

### The Deployment Pipeline:
1. **GitHub (`main` branch):** The single source of truth for code.
2. **Cloudflare Pages (Webhook):** When code is pushed to GitHub, Cloudflare automatically pulls the repo.
3. **Build Process:** Cloudflare navigates to the `/web` directory, runs `npm install` and `npx next build`.
4. **Static Export:** Next.js generates pure HTML/CSS/JS files (using `output: 'export'`) and bakes the JSON data directly into the build for lightning-fast global delivery.
5. **Edge Network:** Cloudflare serves the site from its global edge network, connected to the custom domain `credibilityboard.com`.

## 6. 🤖 Crucial Rules for AI Agents & New Devs
If you are an AI agent or new developer reading this document to assist with development, you **must** respect these constraints:

1. **Respect the Static Build:** The frontend *must* remain a static export (`output: 'export'`). **Do not introduce server-side `fetch` calls to `localhost` or external APIs in `page.tsx` during the build phase**, or the Cloudflare build will crash with a prerender error.
2. **Data Flow:** If you need to update the data on the site, update the Python engine to regenerate `web/data/TFCI_frontend_payload_v2.json`, then commit the new JSON.
3. **TypeScript:** Strict TypeScript checking is currently bypassed in `next.config.js` (`ignoreBuildErrors: true`) to allow the static build to pass. When fixing UI bugs, try to write clean types, but do not break the build if minor type mismatches occur.
4. **Deployment:** To force a fresh build if Cloudflare gets stuck, go to Cloudflare Dashboard → Settings → Build → Disconnect and Reconnect the Git repository.
